Plain-language summary

This audit ran in two passes and closed twenty-four findings. The first pass fixed eleven. The second recovered the work of five parallel audit agents whose results never reached the first pass; every recovered claim was re-verified against the file, one was found wrong and corrected, and thirteen survived. All are now fixed.

Three of them were production defects rather than test gaps. The Markdown sanitizer let a link scheme padded with tabs or newlines through as a harmless relative link, which the browser then resolved to javascript:. A remote folder path beginning with a tilde reached a shell command unquoted, and fixing it exposed a second hole the finding had not named, since the ~user/ branch left the username unquoted too. And a text-selection drag ending on a checkbox left it visibly toggled against a file that never changed.

The rest was the suite lying about what it covered. GitStateWatcherTests imported no Redmargin module at all: it built its own file-system event source and asserted that macOS delivers write events, and that Swift's hasPrefix works on a string the test had just written. Four more tests had the same shape. Three tests asserted nothing, one of them consisting only of a comment saying it was covered elsewhere. Two files hardcoded a developer's home directory, the Linux suite had no runner, and the command the project designates for verification ran no tests at all. Each of those is closed, and each new test was checked by reintroducing the defect and confirming the test fails.

Two things worth keeping in view. The App Nap tests were passing in a class that build.sh skips, so they had never run; only the mutation check revealed it. And writing the Linux runner reproduced a bug this repo has hit before, where pkill -f redmargin-server matches the command line carrying that string and kills its own session.
